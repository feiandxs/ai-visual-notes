    「海王星」项目：「稳定」表象背后的求索

    Windows 95 之后，Windows 的外观看上去稳定了好几年。可微软内部一直在试另一条路：把浏览器揉进系统，用「页面」代替「桌面」和「窗口」，围绕「项目」和「任务」组织一切。这条路最终没走通，却留下了很多影子。

    1990 年代末，微软从「Windows 桌面更新」到 RedShark 构想，再到 Neptune 的「活动中心」，试图建立一个以任务为导向、以页面替代桌面与窗口的界面。它因理念太超前、底层技术跟不上而搁浅，但帮助中心、全屏开始屏幕等设计，都能在后来的 Windows 里找到。[1]

    01

    「操作系统网页化」？

    把一个 .html 文件的后缀改成 .hta，它为什么就像变成了一个独立程序？

    原文先请读者做一个实验：在 Windows 上随便找一个不太复杂的网页文件，把后缀从 html 改为 hta，双击打开，网页内容照常显示，但它看起来已经是一个独立的程序。这个小小的 hta 文件，是微软在上世纪末那场「操作系统网页化」试验留下的遗产。随着 IE 内核逐渐从 Windows 中移除，hta 文件将来可能不再受支持。

    改后缀实验：切换文件后缀，看同一份网页由谁来承载、外面套了什么。
    本页补充（非原文）：HTA（HTML Application）由系统里的 mshta.exe 承载运行，不经过浏览器的安全区限制，权限与普通本地程序相同，因此可以读写文件、调用系统组件。这也是它能「像程序一样」的原因，同时让它成了一种常被滥用的脚本载体。[2]
    02

    Windows 98 = Windows + IE

    「Windows 桌面更新」到底往桌面上加了什么？

    1997 年 9 月，Internet Explorer 4 发布，同时为 Windows 引入「Windows 桌面更新」。它在 Win95 与 NT 4.0 上是可选更新，在默认装了 IE4 的 Windows 98 上是内置功能。它的目的是加强 IE 与 Windows 的集成：资源管理器用上了类似 IE 的界面；任务栏引入了工具栏和「快速启动」栏；还有「活动桌面（Active Desktop）」和「频道栏（Channel Bar）」。活动桌面允许把网页之类的 Web 项目设成壁纸并直接在桌面上与之交互；频道栏用来实时接收并在桌面上显示网站的信息。

    Windows 98 桌面线框：逐个打开「桌面更新」带来的四项改动。原文配了两张截图：装了桌面更新的 Windows，以及把 Yahoo! 网站设为桌面的 Windows；这里都画成线框。

    微软为什么在这时执着于把浏览器和 Windows 绑在一起？当时正是「第一次浏览器大战」最激烈的时期。据说网景创始人马克·安德森（Marc Andreessen）曾放话：

    「未来，在网景面前，Windows 将被简化为一堆设计拙劣的设备驱动程序的集合。」

    为了与网景竞争，微软借 Windows 的力量推 IE 的份额；加上人们普遍看好互联网的潜力，微软开始了「操作系统网页化」试验。前面的 hta 就是随 IE5 引入的特性，当时也被用在欢迎程序等系统文件里。副作用是：IE 后来失去份额乃至停止支持时，怎样把它从 Windows 里剥离成了不小的难题。不过原文关心的是另一件事：这些抬高自带浏览器地位的举措，如何引出了一场重构 Windows 界面的试验。

    从「RedShark（红鲨）」到「Neptune（海王星）」

    Ben Slivka 回顾这个项目时，借 Microsoft Teams 和 Slack 来说明当年的愿景：「Microsoft Teams 和 Slack 都走在实现我们当年愿景的道路上，但两者都有复杂性和局限性。我们的主要见解是：项目应该是组织原则，而不是团队。」

    04

    神秘的「海王星」

    一个只公开过一个构建的版本，在 Windows 家谱里处在什么位置？

    Neptune 出现时间很短，目前公开的只有一个构建，是 Windows 史上一个神秘的存在，但其中一些设计对当时和后来的 Windows 影响深远。它本来要接替 Windows 98，却基于 NT 内核而非 98 的 9x 内核；它的一些功能被同时期的 Windows Me 采用；最后它又与旨在继承 Windows 2000 的 Odyssey 项目（至今一个版本都没公开）合并，成为代号「Whistler」的项目。

    家谱图：点任意一个节点看它的位置。橙色是 9x 内核，紫色是 NT 内核，虚线框是没有正式发布的项目。
    本页补充（非原文）：Windows Me 于 2000 年 9 月发布，是最后一个 9x 内核的 Windows；Whistler 最终以 Windows XP 之名在 2001 年 10 月发布，从此家用版也转到 NT 内核。[3]
    05

    活动中心：以任务为中心

    「根据任务目标而不是工具来表述选项」，点起来是什么感觉？

    Neptune 的「活动中心（Activity Centers）」就是对上述想法的实践。它是一种以任务为中心的新界面，与前文的「项目」概念相似，都从用户要完成的事出发；用 HTML 与 Win32 API 组合编写，跑在一个叫 Mars 的 Web 框架上。由于 Neptune 和 Windows Me 的开发互相交织，实际版本里 Neptune 的活动中心用的是 Me 的 Millennium 代号。

    据科技评论员 Paul Thurrott 的描述，它计划包括照片中心、音乐中心、游戏中心、帮助中心、家庭网络配置中心和自动更新页面，遵循「感应式导航」的设计原则（下方模拟器里列出五条）。「起始页」可以通过活动桌面设为桌面，放着推荐任务（查看邮箱、浏览网络等）和最近的程序/文件。每个中心的主页提供主要任务，用户也能自定义；次要任务页面给出完成单个任务的明显步骤，标题往往是一个问题或一句描述。各中心都有导航栏，可以定位页面或回到主页。

    活动中心模拟器：从起始页进入照片中心，走一遍「扫描」或「编辑图片」。每到一页，下方会亮起这一页体现了哪几条感应式导航原则。页面标题里的两句话取自原文，其余界面为示意。

    原文还提到 Neptune 引入的其他特性：自动更新与自托管机制（后来 Windows 的 Insider 项目也用了类似机制），以及「快速启动」功能（类似功能后来出现在 Windows 8 中）。原文配有 Neptune 的项目 Logo、活动中心概念动图、实际版本里的活动中心和 Neptune 升级提醒的截图。

    Paul Thurrott 评价：「如果微软能够成功，活动中心对于新用户和缺乏经验的用户来说将是一个巨大的福音……从逻辑上讲，我们会使用计算机来完成任务，而不是漫无目的地在无连接性的用户界面中徘徊……」但他也指出局限：活动中心更适合新手，熟练用户更愿意直接找工具；而且它强调简单和可发现，不强调效率，所以不适合频繁重复的任务。

    新手福音，老手负担：同一件事「挑一张照片拿去编辑」，比较两条路径。切换用户类型、拖动每周重复次数。步数是本页为说明 Thurrott 的论点而设的假设值，不是测量数据。
    06

    向现实妥协

    试验搁浅后，这些想法各自去了哪里？

    重构界面的试验最终不了了之，RedShark/Neptune 的理念没有被微软接受。Ben Slivka 猜测，比尔·盖茨觉得它听起来太像大型机，而微软正是靠 Windows 和个人电脑消灭了大型机。他感叹：「我们实在太超前于时代了。」现实情况是，当时的底层技术也不足以支撑类似活动中心的界面。

    Windows Me 部分实现了活动中心的设计；随着 Neptune 并入 Whistler，试验渐渐没了下文。用原文的话说，内部「风高浪急」，却很少有「浪花」溅到最终版本里。已经进入 Windows 的那些功能也命运各异。

    07

    「海王星」的重生

    全屏开始屏幕的种子，是什么时候埋下的？

    在 Whistler 里活动中心基本停止了开发，但 Build 2410 做了一个不起眼的尝试：把活动中心的「起始页」映射到「开始」按钮上，也就是考虑用起始页替代开始菜单。同时仍然可以按 Shift+Win 打开传统的开始菜单，原文认为这比 Windows 8 的设计更人性化。

    点「开始」：在 Build 2410 下分别不按 / 按住 Shift 点开始按钮（勾选「按住 Shift」，或真的按着 Shift 键点），再切到 Windows 8 对比。界面为示意线框。
    本页补充（非原文）：Windows 8（2012 年 10 月）去掉了传统开始菜单，开始按钮也不再常驻任务栏；Windows 8.1 恢复了开始按钮，但点开仍是开始屏幕；传统样式的开始菜单到 Windows 10 才回来。[4]

    回看 RedShark/Neptune 对如何组织操作系统的思考，与今天「云计算」的概念十分相似。前微软高管 Brad Silverberg 评论：「Neptune 团队对基于云的计算有着出色的了解。」活动桌面「把网页设为桌面」的功能，也在今天许多动态桌面软件里实现了。

    而「以项目/任务为中心」的界面，后来被一位叫 Jason Yuan 的设计师翻新，提出了一套以任务为导向的界面。巧合的是，他也用一颗行星给它命名：Mercury（水星）。

    「稳定」的 Windows 背后，微软曾经认真想过让电脑围着「你要做的事」转，而不是围着「程序」转。这个想法在当时太早，却一直没有消失。
