Windows 1.0 到 3.11
    设计 · GUI 史 · Windows

    35 年的 Windows 系统界面设计是如何演变的？

    作者在模拟器里把 Windows 1.01、2.1、3.0、3.1 逐个装了一遍，看第一个十年里的 Windows 长什么样、能做什么、缺什么。这一页把原文的截图换成可以动手的示意界面。

    Windows 1.0 并不只是 MS-DOS 的一层外壳，它从第一版起就有自己的图形 API。此后不到十年，它从一个安装包只有 1.5 MB 的简陋环境，长成了有 TrueType 字体、多媒体和联网能力的完整系统。[1][2]
    先看全景。切换年代，看当年屏幕大致的样子（示意线框，配色和布局是概括，不是像素还原），下面的标签是这一版有没有某项能力。
    DDmitrii Eliuseev（原作者） 优优设网 · 土拨鼠（中译）

    原文：Dmitrii Eliuseev，「Windows 1.0, 2.0, 3.0 — How do they look today?」，UX Collective（2021-03-20）；中文译本《35年的 Windows 系统界面设计是如何演变的？》刊于优设网，译者署名「土拨鼠」。本页按原文的叙述顺序展开，并加了几处标注为「本页补充」的核对与延伸，其中包括对照英文原文发现的几处译文出入。

    01

    背景：电脑从冰箱大小缩到桌上

    1985 年 Windows 1.0 出现之前，个人电脑世界发生了什么？

    原文从五十年前讲起：那时电脑有冰箱那么大，价格相当于一辆跑车。硬件变小、变便宜之后，个人电脑起步，IBM 也想进场，却没有适合新硬件的操作系统，于是找上了当时只有约 30 人的微软。

    点时间线上的节点，看原文对每个节点说了什么。
    本页补充（非原文）：原文写 Altair 8800 是 1974 年「被制造出来」。它确实在 1974 年设计、10 月做出原型，但公众第一次见到它是 1975 年 1 月号《大众电子》（Popular Electronics）的封面，那期杂志 1974 年 12 月 19 日上市，所以不少资料把它记作 1975 年。[3]
    02

    模拟系统：今天怎么亲手跑一遍

    手边没有能跑 MS-DOS 的老电脑，怎么体验 1985 年的 Windows？

    作者的办法是模拟器，而且最好用真实的磁盘映像跑「真实的」软件，这样才能真正理解它怎么工作。原文给了两条路：直接在浏览器里运行各种老系统映像的 pcjs.org；或者在本机装 DOSBox，从 Windows 1.0 到 Windows 95 都能跑。标准 DOSBox 只有命令行，从 img 文件挂载外部驱动器有点烦，作者用的是带图形界面的 DOSBox SVN Daum 版。

    切换两种方案，看「一台现代电脑里跑 Windows 1.01」是几层东西叠起来的。
    本页补充（非原文）：DOSBox 的衍生版 DOSBox-X 的文档说明，Windows 1.0 到 3.11 一般可以直接在它自带的 DOS 环境里运行；Windows 95 之后的版本则需要先在模拟器里引导它们原本依赖的 DOS。[11]（译文里的「MA-DOS」是笔误，原文是 MS-DOS。）
    03

    Windows 1.01（1985）：窗口只能平铺

    第一版 Windows 已经有了什么，又缺什么？「只能在一个垂直维度上调整窗口」到底是什么手感？

    1.01 是第一个公开版本。作者看到的是非常基础的设计，但窗口、滚动条、菜单这些 UI 组件都已经齐了；应用之间可以复制粘贴，不过只限文本，不能复制文件或文件夹；鼠标和 Mac 一样只用一个键；窗口可以最大化或调整大小，但只能在一个垂直维度上调；没有 Alt+Tab，没有桌面壁纸。自带的应用不多：能做简单可视化排版的文本编辑器、计算器、日历等，可执行文件清单很短。

    打开几个应用，再拖窗口之间的分隔条，或点标题栏右端的方块最大化。然后切到 Windows 2.x，看同样几个窗口能不能叠起来、随便拖。
    本页补充（非原文）：Windows 1.0 于 1985 年 11 月 20 日发布。它的窗口不能互相重叠，只能并排平铺，只有对话框可以浮在其他窗口上；最小化、最大化当时叫 iconize 和 zoom。自带程序包括计算器、画图（Paint）、记事本、Write、终端、时钟、卡片盒（Cardfile）、剪贴板、打印池、控制面板和黑白棋（Reversi）。窗口可以重叠是从 1987 年 12 月的 Windows 2.0 开始的。[4][5]上图的平铺规则是概括：本页让窗口上下分行、只能拖高度，用来对应原文那句「只能在垂直维度上调整」，真实 1.0 的平铺布局更复杂。
    04

    「初代 Windows 只是 MS-DOS 的外壳」只对一半

    为什么作者说这个常见说法只有 50% 正确？

    对的那一半：在 Windows 里确实能运行 MS-DOS 程序，很多人也就是这么用的。错的那一半：Windows 带来了一套全新的图形界面 API，开发者可以用它写原生运行在 Windows 上的软件，用上按钮、滚动条、字体等新控件。这套 API 和 MS-DOS 不兼容，旧代码要重写或从头做，于是新系统刚发布时没有应用，成了「鸡与蛋」问题。所以 Windows 不只是 Norton Commander 那样的外壳，它有自己的 API 和 UI 库。

    选运行环境，再选一个程序「运行」。四种组合的结果会记在下面的表里。

    作者也承认，第一版 Windows 的功能比 Macintosh 有限得多。但 IBM PC 比 Mac 便宜近 30%，而在 9 到 12 英寸、640×480 分辨率的显示器上，同时开很多窗口没那么要紧，许多应用用全屏文本界面就够了，比如上面的 Lotus 1-2-3 和 DOS 版 Word 1.1。和它们比，第一版 Windows 的界面已是进步；而且 Windows 1.0 开箱就支持彩色屏幕。

    05

    Windows 2.1（1988）：三年只走了一小步

    1200 bit/s 的调制解调器上，「加载这篇文章要十分钟」是怎么算出来的？

    几年后界面有了改进，但仍然没有桌面、没有开始按钮、没有任务栏，只有最小化后的应用图标可以在屏幕上挪动。作者觉得三年的变化没想象中那么大，猜测是因为当时微软主要的利润并不来自 Windows，大部分开发者在忙别的项目。有意思的是，记事本（Notepad）这类应用直到今天也没怎么变。联网能力很有限，互联网还没出现，「终端」应用可以通过调制解调器（modem）拨号。作者开玩笑说，按 1200 bit/s 的速度，加载他这篇文章大概要十分钟，不过那时 HTML 也还没被发明。

    选一个线路速度，看几样东西要传多久；再点「按这个速度播放原文开头」，亲眼看看字是怎么一个个过来的。
    本页补充（非原文）：本页按串口常见的 8N1 格式估算，每传 1 个字节要占 10 个比特（起始位 + 8 位数据 + 停止位），所以 1200 bit/s 约等于每秒 120 字节。英文原文正文约 9 KB，只传文字也就一分多钟；十分钟对应约 72 KB，原文配有二十多张截图，算上图片只会更久。这是对作者那句玩笑的数量级核对，不是原文给出的计算。Windows 2.1 于 1988 年 5 月 27 日发布；2.0 起窗口可以重叠，并改用了「最小化 / 最大化」这两个说法。[5][6]
    06

    Windows 3.0（1990）：今天看也不算过时

    3.0 能拖放文件了，却还不能用长文件名。「8.3 文件名」把一个普通文件名变成什么样？

    Windows 3.0 比前辈都成功，原文说第一年就卖出 400 万份。作者觉得它的界面今天看也不错，因为界面潮流「回归」了扁平和低饱和度的颜色。文件管理器和程序管理器成了独立应用；文件终于可以拖放了（Mac 几年前就能做到）；但还用不了长文件名，DOS 遗留下来的「8.3 文件名」一直存在到 Windows 95。可用的应用也越来越多：1990 年发布的 Word 2.0c，安装程序到今天都没怎么变，编辑器功能足够处理文本，而安装包只有 8 MB。

    输入一个今天常见的文件名，看它在 8.3 规则下会被截成什么样；点「存入目录」可以连续存几个开头相同的文件，看 ~1、~2 怎么来的。
    本页补充（非原文）：8.3 指主名最多 8 个字符、扩展名最多 3 个字符，只能用大写字母、数字和少数符号。Windows 95 和 Windows NT 3.5 引入 VFAT，长文件名另存在额外的目录项里，同时为老程序生成一个短名：去掉空格和多余的点，把 + 等字符换成下划线，转大写，主名截到 6 位后接 ~1，扩展名截到 3 位，重名就递增数字。上面的演示按这条规则实现，只模拟了前 9 个序号。Windows 3.0 于 1990 年 5 月 22 日发布，Wikipedia 给出的销量是发布六个月卖出 200 万份，与原文「第一年 400 万份」并不矛盾，但本页没找到后者的出处。[7][9]
    本页补充（非原文）· 译文核对：中译本写「文件可以被缩放」，英文原文是 drag and drop，即文件可以拖放。
    07

    Windows 3.1（1992）与 3.11（1993）：字体、多媒体、联网

    外观变化不大，那 TrueType 矢量字体比老的点阵字体强在哪？

    这是原文评测的最后一个版本。界面上差别不多，但有三件事值得说：

    • TrueType 字体。用贝塞尔曲线描述字形的矢量字体，可以随意缩放而不损失质量，TTF 文件今天还在用。
    • 多媒体。新增媒体播放器和录音机，多媒体时代开始，第三方也开始做音频处理软件（原文配图是 Creative WaveStudio）。
    • TCP/IP。电脑终于能连上互联网了，尽管那时大多数人还不知道这个词。
    拖动字号滑块：左边是一套固定 10 像素点阵字体被放大，右边是轮廓字体在每个字号重新绘制。
    本页补充（非原文）：Windows 3.1 于 1992 年 4 月 6 日发布，自带 TrueType 后用户不再需要 Adobe Type Manager 这类第三方工具来获得可缩放字体；媒体播放器可以放 MIDI 和 AVI，录音机可以录放和编辑 WAV。TrueType 用的是二次贝塞尔曲线（PostScript Type 1 是三次）。至于 TCP/IP，Windows 3.1 本身并不带，而是 1993 年 11 月 8 日发布的 Windows for Workgroups 3.11 后来通过一个 32 位网络组件加装获得，原文说「该版本添加了 TCP/IP 支持」是笼统说法。[8]

    另一个里程碑：Photoshop 在 1992 年推出第一个 Windows 版 2.5，此前只有 Mac 版。它还不支持图层，打开作者那张 800 万像素的图要 5 秒左右，这在 1992 年是巨大的照片尺寸。令人意外的是界面没变太多，裁剪、色阶、曲线、加文字、模糊或锐化这些基本操作，今天用它也做得了。

    本页补充（非原文）· 译文核对：中译本写「8 万像素」，英文原文是 8 MPx，即 800 万像素；原文还说之前的 Photoshop 都只有 Mac 版，中译本漏了这句。按每像素 3 字节（24 位色）算，这张图未压缩约 24 MB，在上面的调制解调器演示里可以看看它要传多久。

    编程：Visual Basic 1.0 把界面变成可以「画」的

    「可视化编辑资源和事件处理程序」到底是什么意思？为什么作者做的 exe 在 Windows 10 上跑不起来？

    原文最后一件要提的事是编程方式的新概念：1991 年发布的 Visual Basic 1.0 是一种新的 IDE（作者说不确定 1991 年有没有这个词）。应用的资源和事件处理程序可以可视化地编辑，这个做法一直沿用到今天。建好项目、「编译」后（作者不确定 Basic 当时是不是真的编译器），就得到一个能在 Windows 上原生运行的 exe。

    本页补充（非原文）：Visual Basic 1.0 于 1991 年 5 月发布，窗体靠拖放控件搭出来，代码挂在控件的事件处理程序上，拖放设计来自 Alan Cooper 团队的原型。早期 VB 是解释执行的（编成 P-code），直到 VB 5.0 才能编译成原生机器码，所以作者「不确定是不是真的编译器」的疑问是有道理的。跑不起来的根本原因是位数：运行 16 位程序要靠 NTVDM 组件，它只存在于 32 位版 Windows，64 位 Windows 根本没有，Windows 10 是最后一个带它的版本。[10][12]
