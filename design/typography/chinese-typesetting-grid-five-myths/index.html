    中文排版网格系统的五大迷思

    中文的网格不是从瑞士借来的。方块字本身就是「一字一格」，版心、栏宽、标题、缩进，都应该用「占几个字、占几行」来算。下面每个演示都用真实的中文和 CSS 现场排出来，你可以亲手调参数，看网格什么时候对齐、什么时候散架。

    网格的本质与方块汉字的「字格」一致：先定正文字号与行距画出稿纸，再按「字」与「行」定版。但网格只是工具，要「活用」而不能「死用」：既不能强求所有字符纵横对齐，也不能拿西式网格拉个文本框就放任不管。[1]
    刘Eric Q. Liu（刘庆） 钱钱争予

    原文：《中文排版网格系统的五大迷思》，The Type「孔雀计划：中文字体排印的思路」系列，2020-01-28；署名据剪藏页元数据为 Eric Q. Liu 与钱争予。原文讨论的对象是「编辑设计」，即书刊杂志与长文网页的排版，不是海报类版式。本页忠实于原文的叙述顺序，原文插图均已重绘为可操作的演示，并加了几处标注为「本页补充」的核对与延伸。

    01

    迷思一：网格是「舶来品」

    网格真是瑞士国际主义风格带来的洋玩意儿吗？方块字自己就是一格一格的。

    原文指出，布罗克曼（Josef Müller-Brockmann）在《平面设计中的网格系统》的案例部分就专门举了日文杂志《艺术手帖》，写道「日文与中文一样，都是建立在正方形的基础上」。汉字文化圈的报刊「定版设计」历来用方格稿纸：先定「基本正文字号」「基本正文行距」画出稿纸，再让标题、分栏都以「字」「行」为单位，绝不会出现「栏宽 20.15 个字」这种尴尬的宽度。[1][2]

    同一段文字，三种网格。原文用 InDesign 对比了西式「基线网格」与中式「框架网格」。这里换成现场排版：切到方形模块网格再拖动边长，你会看到西式网格在什么条件下变成中式字格。文字取自鲁迅《朝花夕拾·小引》。
    小型报纸的定版设计样（示意重绘）。原文配图左边是手绘的定版样，右边是 InDesign 的复现：所有分栏、标题都落在正文字号的网格上。点任一区块，看它用「字」「行」怎么描述。
    点一个区块。

    西文排版本没有「格」，古登堡以来很长时间只有「分栏」，后来为了更精细地控制版面才另外定义出网格。中文则相反：方块字决定了「一字一格」，网格本就蕴含在字体排印内部，可以从一个字格扩展到整个版面。会用网格的人都知道单位网格越小越灵活；把西式网格的单位格做成一个正文汉字大小，中西网格就融合了，中式网格只是它的一个特例。[1]

    字格量的是哪个框？点一个字符，画布上会现场测出它在本机字体里的「字身框」（虚线，排版时占的格子）与「字面」（实线，笔画实际覆盖的范围）。
    本页补充（非原文）：字格对应的是「字身框」（金属活字的字身、数字字体的 em 框），不是笔画的外轮廓「字面」。汉字的字身是正方形，字面略小于字身并大致居中，所以一个个字身框可以无缝拼成稿纸；西文字母的字身宽度各不相同（比例宽度），拼不成方格。上面的测量用浏览器 Canvas 的 measureText() 现场完成，不同系统字体结果会有出入。[5]
    02

    迷思二：做版式先留边距

    先定页边距、剩下的给版心，为什么放在中文上就会出零碎？

    西文没有字格，习惯「先算边距，再剩下版心」，甚至用黄金分割这类无理数比例来定版心；西文字母本身比例宽度，长文多用左对齐，两端对齐时也能灵活伸缩，所以对文本框宽度没有严格要求。中文传统恰好相反，是「先算版心，再余白」：

    以文字为主的出版物，在确定版心的尺寸时，是以排版正文字号的字数来确定行长（即版心宽度），再以行数和行间空距之和为版心长度。——《实用出版与印刷工作手册》（第二版），印刷工业出版社，1998（转引自原文）
    一张 130 mm 宽的书页，两种工作流程。选字号，再分别拖「页边距」或「每行字数」。蓝色虚线框是版心，浅灰方格是从版心左边起算的整字格。青色字表示它已经偏离字格。

    中式流程先定栏宽（比如每行 25 个字），再把版心摆上页面；天头、地脚、切口、订口这些「余白」是页面减去版心之后算出来的，是「余」出来的，不是事先「定」出来的。先定边距再套汉字，版心宽度往往不是字宽的整数倍，再加上两端对齐，字距就失控了。传统雕版与活字印刷，一直都是先在书框里「套格」，再「摆书」。[1]

    本页补充（非原文）：上面的演示把切口与订口取成相等、天头与地脚也取成相等，只为突出「余白是算出来的」；真实书籍的四边余白通常各不相同。网页里对应的做法是把版心宽度写成字号的整数倍，例如 max-width: 25em，而不是写成 80% 这类与字号无关的值。
    03

    迷思三：不知「占字」「占行」为何物

    「空两格」「占三格」「占三行」这些中文排版里司空见惯的说法，为什么在按西文思路做的软件里那么难实现？

    有了稿纸式的基础网格，所有元素都用「占格」「占行」来定位。原文列了四组对照：段首缩进「空两格」，西文用点或毫米；花名册每个名字「占三格」，西文用 tab 对齐；小标题「占三行」，西文靠段落间距；栏间距「占两个字」，西文用绝对单位。1927 年鲁迅为《朝花夕拾》写的排版要求里，字号写「2」「5」（二号、五号），行距写「空两格」「空一格半」。国标 GB/T 15834—2011《标点符号用法》也说「句号占一个字位置」。[1][6]

    占字：段首空两格

    同一段话，两种缩进写法，都是浏览器里的真实 CSS。拖字号：text-indent: 2em 永远是两个字；text-indent: 8mm 只在某个字号下碰巧接近两个字，其余时候都落在字格中间。背景竖线是字格。

    原文提到，Adobe 软件「段落」面板里的「段首缩进」是按西文流程设计、以毫米为单位的；InDesign 为中文准备的段首缩进放在「中文排版设置」（2020 版之前叫「标点挤压设置」）对话框里，还能设段首缩进与前括号的关系。[1]

    占字：花名册「占三格」

    人名列表。正统排法是每个名字占三格：两字名中间空一格，与三字名对齐；名字过长时，下一个名字不是空一格接着排，而是从下一个网格单元起排。切换两种排法，看竖向能不能对齐。蓝色粗线是「三格 + 一格间隔」的网格单元。

    占字在网页里：em 与 rem

    原文说，CSS 的 em 来自印刷里的「全角」，数值等于字号，写 2em 就是「空两格」。rem（root em）则相对根元素的字号：根上定一个正文字号，就等于定了一个「字格」，其他元素都按它的倍数定位。em 相对父元素，会层层继承，嵌套多了容易迷失；rem 直指根元素，清晰明了。原文认为这正是熟悉东亚排版的专家们极力推动导入 rem 的原因。[1][3]

    四层嵌套，每层字号都设为 0.875，缩进都设为 2。切换单位，看各层缩进是否还落在根字格（背景竖线，间距 = 1rem）上。下面的数值是从浏览器 getComputedStyle 读出来的。

    占行：标题是正文行的倍数

    在排版中，所有标题都必须是正文行的倍数。——《当代排版技术概论》第二版，1994（转引自原文）
    所谓标题的占行，是指在标题排版中，它所占的版面位置应是正文行的倍数。所谓对行，就是在一个版面上和一本书中，所有对应的正文字行都处于一个水平位置上。——《实用出版与印刷工作手册》第二版，1998（转引自原文）
    两栏正文，左栏插入一个小标题。西式做法用「段落间距」控制标题上下的空，标题字号又与正文不同，于是标题之后的左栏正文与右栏错行。切到「占二行 / 占三行」，标题块高度变成正文行高的整数倍，两栏重新对行。背景横线是正文行。

    金属活字时代的常见做法是「一级标题约占四五行，二级标题约占二三行，三级标题约占一二行」，还有「双行题目占三行」这样的操作。当代排版工具多用西文的段落间距来控制小标题，对行不是做不到，而是标题字号与正文不同时需要认真计算。网页上的「纵向韵律」（vertical rhythm）一直是难题：W3C 的 CSS Rhythmic Sizing 已久未更新，最接近「占行」的 line-grid 草案仍在争论之中；行高之所以复杂，是因为前端无法预知最终在什么平台、用哪个字体的什么度量来渲染。[1][4]

    本页补充（非原文）：上面的演示用的是最朴素的办法：把小标题块的 height 直接写成正文行高的整数倍，并把行高写成固定像素值。这只在标题不折行时成立；标题折成两行、字体回退导致行高变化时就会失效，这正是原文说的「每个步骤都有太多变数」。原文作者在播客「字谈字畅」第 103 期对行高问题有更多讨论。
    04

    迷思四：过犹不及地认为「齐就是好」

    只要所有字符都全宽、不调整，版面就能纵横对齐。可这样排出来真的好读吗？

    破坏纵横对齐的「非全宽元素」是三类：可调宽度的标点、比例宽度的阿拉伯数字、混排在行内的西文字母。如果执行「网格绝对优先」，可以简单粗暴地把标点都排全宽、不做避头尾，数字和西文都换成全角，自然纵横对齐。原文举了台语汉字本《圣经》为例。[1]

    同一段中西混排文字。先点两个预设，再单独开关三项处理，或拖动行长。红字是落在行首的标点（违反避头尾），青色字是偏离字格的字。

    原文的比喻：走路是为了到达目的地，路要平坦，但也不能像雪原冰面一样过于平滑，不仅容易跌跤，还会因为没有参照物而迷失方向。阅读也一样，太平整的文字列容易跳行，也容易让人困乏。The Type 早在 2013 年就撰文《纵横对齐不是现代方法》：现代中文离不开标点，就必须认真调整标点宽度、做避头尾和换行位置处理；混排的数字与西文，先在编辑层面做正字法检查（比如权衡用阿拉伯数字还是汉字数字、夹杂的西文能否改用中文词），再选择形式（比如竖排时合理采用全角字符）。[1]

    本页补充（非原文）：上面的「标点对开」是简化模型：所有标点一律排半宽，没有实现相邻标点挤压、行尾标点悬挂等完整规则；中西文之间统一加了四分之一字宽的间隙。完整规则见 W3C《中文排版需求》（clreq）。CSS Text Level 4 草案里的 text-spacing-trim 属性就是为网页上的标点挤压准备的，各浏览器支持程度不一。[5][7]
    05

    迷思五：一蹴而就地认为「网格只用来定文本框」

    文本框拉好了，框里每一行的字格就不用管了吗？

    《平面设计中的网格系统》日文版监修白井敬尚说过：「网格系统并不是一种单纯地对页面进行分割手法，而是要在理解字号、行距这些排版基本构造的基础之上才能成立。」原文拿三本市面印刷品举例：文艺书每段末行字距不同、甚至整段字距不同；中西对照杂志迁就西文网格，段末行字距明显不同；繁体杂志的「疏排」排法不正确。这正是迷思二演示里看到的现象：行长不是字号整数倍，正文行被拉开而段末行不拉，两种字距同处一段。InDesign 东亚版因此专门有「水平/垂直网格工具」，文本框本身就带字格。[1]

    一行里有奇数个半宽标点，多出的半个字怎么办？重绘原文的三行示意：第 1 行没有标点；第 3 行两个半宽逗号合起来正好一个字宽，逗号之后的字偏移半格（浅绿底），第二个逗号之后又回到网格上；第 2 行只有一个半宽逗号，行尾空出半个字。选一种处理方式。

    活字时代工序要尽量少，所以把多出的半个字宽加在逗号后面，等于把这个逗号改回全宽：空隙略显眼，但它标出了行内最大的停顿，调整只限于标点，这一行也保持了网格对齐。照排时代更多做两端对齐，把半个字宽均摊进每个字距：活字时代找不到这么薄的铅空，也不可能每个字后手动加空。均摊的空隙不显眼（行越长越不明显），但这一行的字距与上下行都不同（行越短越明显），破坏了「密排」原则，所有字都偏离网格，三行字有三种阅读节奏。原文的结论是：两种方法没有对错，只是风格之别；「优先网格对齐」选左，「打破网格制约」选右，关键是妥协是否合理、是否与设计逻辑对应。[1]

    小结：是参考线，还是金科玉律？

    网格扎根于方块字的字格之中，但它终究是工具。
