TREE(3) 为什么这么大
    可视化导读 · 知乎问答 · 大数数学

    TREE(3) 的规则那么简单，
    为什么它的值那么离谱的大？

    两位答主给了两个方向的回答：大老李一句话点出 TREE 函数有限的根源——「良拟序」；HypCos 则反过来说：TREE 的规则其实并不简单，真正简单的规则——几十个字符的 JavaScript——就能造出远超想象的大数。本页先讲 TREE 游戏本身，再沿着 HypCos 的「大数高尔夫」阶梯一路往上爬。

    一句话：衡量大数不能靠写出来比，只能比「增长率的层级」——这把尺子叫快速增长层级（FGH），刻度是序数。

    01教学补充（标准表述）

    TREE 游戏：一棵一棵画树，不许「嵌入」

    用 n 种颜色给顶点上色，画一串树 T₁, T₂, T₃…：第 i 棵最多 i 个顶点，而且前面任何一棵都不能「嵌入」后面的树。TREE(n) 就是这串树最多能画多长。

    规则 ①颜色只有 n 种

    TREE(3) 就是 3 种颜色。

    规则 ②第 i 棵树 ≤ i 个顶点

    越往后允许越大，但一开始很小。

    规则 ③前面的树不能嵌入后面的

    一旦某棵新树「含有」前面任一棵，游戏结束。

    一段合法的 3 色序列。进入视口后逐棵出现，并对每一对（前,后）做检查：✓ 没嵌入。顶点数 1、2、3、4、5 各不超过序号。
    • 直觉：顶点上限随序号增长，可选的树越来越多；但「不许嵌入前面任何一棵」的限制也越积越多。TREE(n) 问的是：两股力量拉扯之下，最多能撑多少步。

    02答主：HypCos（定义）

    什么叫「嵌入」：删点删出来的

    HypCos 的说法：表达树的嵌入，至少要用到「删除子顶点数为 0 或 1 的顶点」这一系列操作的闭包。也就是说，能靠反复删叶子、删单链点把大树削成小树，小树就嵌入了大树。

    左边是大树 B，右边是目标 A。点「下一步」看每次删掉哪个顶点（红色虚线圈）。切换目标：同一棵 B，对 A₁ 削得出来（✓ 嵌入），对 A₂ 削不出来（✗ 不嵌入）。
    • 删叶子（0 个子顶点）：直接去掉。删单链点（恰好 1 个子顶点）：去掉它，把它的孩子接到它的父亲上。有 2 个以上孩子的点不能删。
    • 为什么 A₂ 不行：A₂ 要求两个绿点直接挂在红点下，但 B 里两个绿点的公共祖先是蓝点，蓝点有两个孩子删不掉。这就是 HypCos 说「规则算不上简单」的地方——嵌入不是「子图」那么直白。
    03教学补充

    先算小的：TREE(1) = 1，TREE(2) = 3

    1 种颜色时，第一棵树是一个点，之后任何树都含有这个点，游戏立刻结束。2 种颜色时最多走 3 步。然后 3 种颜色——突然爆炸。

    点「播放」逐步穷举。每一步先列出候选，✗ 表示含有前面的树，被淘汰。
    • TREE(2) 的最优走法：红点 → 绿绿（两点链）→ 单个绿点。第 4 棵树无论含红还是含绿都会嵌入前面的树。
    • 然后是 TREE(3)：题目里说的「离谱的大」就从这里开始。但它仍然是有限的——为什么？看大老李那一句。
    04答主：大老李

    大老李的一句话：良拟序

    「TREE(3) 利用了『良拟序』的一个性质：其中没有无穷递降链和无穷不可比链。」——剪藏里大老李的回答只剩这一句，但它正是 TREE(n) 有限的根源。

    在「嵌入」这个序关系下，有限树构成良拟序：左边两种无穷序列都不存在；于是任何无穷长的树序列里，迟早会出现前面的树嵌入后面的树（右边）——游戏必须终止，TREE(3) 是个有限数。
    • 无穷递降链：一个比一个「小」、永远降不到底的序列。无穷不可比链：两两互不嵌入、能无限列下去的序列。良拟序禁止这两者。
    • 教学补充：这个结论是 Kruskal 树定理。它只保证「有限」，完全不告诉你有多大——而 TREE(3) 大到任何常规记号都写不下。
    05答主：HypCos

    反问：TREE 的规则真的简单吗？

    HypCos 的观点：用很简明的规则就能得到极其巨大的数；相比之下，TREE 函数的规则算不上简单。为了说明「规则能有多简洁」，他列出了 JavaScript 大数高尔夫的成果。

    JavaScript 大数高尔夫：用尽可能少的字符，在 JavaScript 里输出尽可能大的数。结果来自 googology discord 讨论群。语言做了三处调整：
    ① 精确数值不封顶

    不再局限于 ±(2⁵³−1)，足够大，足以让代码不溢出。

    ② 位运算不封顶

    不再局限于 int32。

    ③ x>>y，y 为负数

    相当于右移一个很大的数，把 x 的所有有效数位抹掉。换成左移是未定义行为。

    • 比赛的尺子：字符数。每多一个字符，能到达的数有多大的跃升？下一节的阶梯就是答案。

    07教学补充（原文默认读者知道）

    尺子：快速增长层级 FGH

    f₀ 是「加一」，之后每升一级就把上一级「迭代 n 次」。到了无穷序数 ω，就沿对角线取 f_n(n)。原文所有「相当于 FGH 中的 ω+1」之类的话，都在说代码的增长率落在这把尺子的哪一格。

    拖动 n，看前几级在 n 处的取值。条长按「对数的对数」压缩，否则 f₃ 就已经画不下。
    • f₁(n)=2n，f₂(n)=2ⁿ·n，f₃ 已是指数塔；f_ω(n)=f_n(n) 把下标也变成变量，再往上 f_{ω+1} 把 f_ω 迭代 n 次——原文说这「就是葛立恒函数的增长率」。
    • Hardy 层级 HH是另一把等价的尺子，刻度略有错位（原文在五级运算与 Goodstein 处用的是它）。
    08答主：HypCos

    解剖 33 个字符：超运算是怎么长出来的

    n=y=>x=x--*y?n(y)*n(y-1):9;n(x=9)。全局变量 x 是底数，局部变量 y 是「迭代的层级」：n(0) 是常数 9，n(1) 乘 x 遍得到 9ˣ，n(2) 迭代 x 遍指数得到 9↑↑x……y 每加一，就是 FGH 里的 f_{1+y}。

    选一个 y，看 n(y) 展开成多少个 n(y−1) 的乘积（示意，x 取 4）。
    • x 的两种用法：在 n(y)*n(y−1) 的连续调用之间，x 单纯递减，这相当于把「调用开始前的那个 x」当作迭代次数。
    • 再往上：39～41 字的版本把「无限的序数编码成有限的整数 y」，于是 y 本身可以越过 ω。
    09答主：HypCos

    用一个整数 y 编码一个序数

    41 字代码：y=99 相当于 ω，y=98 是 ω+1……y=1 是 ω+98；y=0 得常数，y=−1、−2 则是有限层级 2、3。42～51 字更进一步：用「y 除以 a 的余数」编码 ω 的倍数，用商编码后面的 +k。

    41 字方案：一条数轴，正数一侧倒着数到 ω+98，负数一侧是有限层级。
    42～51 字方案（以 a=9 为例）：网格每一列是一个余数 r，对应 ω·r；每一行是商，对应 +k。把鼠标放到格子上看它编码的 y 值。
    • 余数为什么要保留：代码里 n(y)+n(…) 中间必须是加法而非乘法，y<0 时用 x−~y = x+y+1 让余数加 1，进入前一个「ω 的多少倍」区域的迭代。
    • 52 字以后：偶数 y 减半、奇数 y 跳区域，编码到 ω²·k；57 字起用「k 阶数」（费马素数等）编码，一路到 ω^ω——并且撞上一个未解决的数论问题：内层结果 x 的「阶」到底有多高。

    12

    总结

    四步看完这个问题。

    1

    游戏规则

    n 色、第 i 棵 ≤ i 点、不许嵌入前面任一棵。嵌入 = 反复删叶子与单链点。

    2

    为什么有限

    良拟序：没有无穷递降链和无穷不可比链，序列必定在某步出现嵌入。

    3

    为什么离谱

    「有限」不等于「可写」；衡量大数要用序数刻度的 FGH 尺子。

    4

    规则其实不简单

    几十个字符的代码就能一路爬到 ψ(Ω_ω) 乃至更高；TREE 的嵌入规则反而更复杂。

    TREE(3) 大，不是因为规则简单；而是因为「有限」和「可想象」之间的距离，远比我们以为的大。
