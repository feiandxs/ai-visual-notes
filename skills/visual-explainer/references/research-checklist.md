# 调研、署名与参考文献规则

## 1. 获取原文：通用顺序

来源不限于知乎：个人博客、Medium/Substack、公众号文章、arXiv/论文 PDF、维基百科、Stack Exchange、GitHub README、Hacker News 讨论、YouTube/播客的文字稿等都可能出现。按下列顺序尝试，前一步成功就停：

1. 用户给的是本地 md：直接读（Obsidian Web Clipper 的 frontmatter 一般有 `source`、`author`、`created`、`title`）。
2. 用户给的是 URL：`WebFetch` 原链接。
3. 被拦（403、登录墙、JS 渲染得到空页）：
   - `WebSearch` 搜「标题 + 站点名」，读摘要和转载页，能拼出署名与大意，但不能把摘要当全文；
   - 有浏览器 MCP（如 Playwright）就用它打开页面读 `browser_snapshot` 的文本；
   - 以上都不行，告诉用户：请用 Obsidian Web Clipper 存成 md 再来，并说明已经尝试了什么。不要靠记忆编造全文。
4. PDF（arXiv、论文）：下载到 scratchpad（不是仓库）后用 Read 工具按 `pages` 分段读；先读摘要、引言、结论，再读正文。
5. 视频/播客：只用有文字稿的来源；没有文字稿就请用户提供，不要凭标题脑补内容。
6. 讨论串（知乎问题、Hacker News、Stack Exchange、论坛）：每个被采用的回答/评论是一个独立来源，分别记录作者、日期、链接。

获取到的原文只放在 scratchpad 或内存里，不写进仓库。

## 2. 署名规则

按顺序取第一个能确认的：

1. frontmatter 的 `author`；
2. 页面 byline / meta author / 文末署名；文中自述（「我是……」）；
3. 站点与标题搜索（WebSearch）看摘要里的作者；
4. 仍然拿不到：署「<站点名>作者（未存档作者名）」，例如「知乎答主（页面未存档作者名）」「某博客作者（未存档作者名）」，并在最终报告里说明。

规则：
- 绝不猜测或编造姓名；搜索结果里不确定是不是同一人，就按第 4 条处理。
- 出处列格式与 README 表格一致：「作者，站点/刊物（日期）」。例：`nazha，nazha.co（2025-01-24）`、`Stephen Wolfram（2024-10-08）`、`知乎答主 贾明子、陈童`。日期用页面发布/编辑日期，没有就省略。
- 多篇回答/多作者要分别列出各自作者，主要来源标「（主）」。页面标题区用 `.authors` 的胶囊逐个列出，页脚写明各自采用了哪一部分。
- 原文链接放页脚「来源与署名」里（外链文本链接可以，外链资源不行）。

## 3. 语言

页面始终中文。英文或其他语言原文照常翻译讲解；专业术语和人名在首次出现时括注原文，如「良拟序（well-quasi-ordering）」。直接引用的原文句子可保留原文并附译文。

## 4. 补充调研与「本页补充」

- 补充内容（原文没有的核对、历史背景、延伸文献、数值验证）必须放进 `<div class="note-add"><b>本页补充（非原文）</b>：……</div>`，不能混进正文叙述里冒充原文观点。
- 页面开头 `.meta` 要有一句话告知读者「加了几处标注为『本页补充』的内容」。
- 能用 JS 在页面里现场算出来的数值（比值、音分、群运算）就现场算，别手抄。
- 凭记忆写的、没有核对来源的事实：尽量别写；一定要写的，在最终报告里逐条列出「未核对」。核对过的写明来源。
- 原文自己有错或存疑：在补充块里指出并给出依据，不要默默改掉。

## 5. 图片

原文图片（zhimg、微信图床、博客图床等）一律不外链、不下载内嵌，用内联 SVG / canvas 重做；重做时按原图表达的信息画，不要照搬水印。页脚写一句「原文插图均已用内联 SVG 和 JS 重绘，未引用外链图片」。

## 6. 参考文献格式

页脚 `<ol id="refs">`，正文中用 `<sup class="c">[n]</sup>` 角标对应序号。

- 第 1 条永远是原文（含它自己的脚注里被你采用的内容）。
- 论文：`作者 (年份). 标题. <i>期刊</i> 卷(期), 页码. <a href="链接">链接文字</a>`（可加 arXiv 编号）。
- 书：`作者 (年份). <i>书名</i>. 出版社.`
- 维基百科：`Wikipedia 条目 X、Y：用到的具体结论`。
- 链接只放文本超链接，不放资源。不确定链接是否有效就不放链接，只放题录。
- 页脚末尾固定一句：「本页由 Claude Code 基于原文与上述公开资料生成，仅供学习；……细节以原文与文献为准。」

## 7. 知乎 403（常见例子）

知乎页面 WebFetch 通常 403，拿不到答主昵称和正文。退路顺序即第 1 节的通用顺序：frontmatter author → 文中自述/署名 → WebSearch「标题 + 知乎」看摘要 → 仍无就署「知乎答主（页面未存档作者名）」并在报告里说明。原文链接放页脚。用户给的是 Clipper 存下来的 md 时正文已有，只缺作者的话按此退路补署名即可。

## 8. 原料类型补充：视频与纯命题

- **视频链接（YouTube / B 站 / 播客）**：先拿字幕，不下视频：
  `yt-dlp --write-subs --write-auto-subs --sub-lang zh,en --skip-download -o "<scratchpad>/%(id)s" "<URL>"`
  没有字幕：只下音频（`yt-dlp -x --audio-format mp3 -o "<scratchpad>/%(id)s.%(ext)s" "<URL>"`），再用本机有的转写工具（whisper / whisper.cpp / mlx-whisper，有什么用什么；都没有就告诉用户并请他提供文字稿）。B 站遇到 HTTP 412 反爬，参考本机 `bilibili-download` skill 里读取浏览器 cookie 的用法。字幕/转写文本即「原文」，之后按文章流程走（自动字幕有误识别，术语要核对）。署名写「频道/UP 主名，平台，《视频标题》（日期）」。下载的媒体只放 scratchpad 或 /tmp，绝不进仓库。
- **纯命题**：没有原文，走「原创」档，见下。

## 9. 忠实度三档：署名与出处示例

三档共用页面规范、验证、索引、提交；差别只在内容来源、标注方式、出处写法。

**转换（faithful）**：严格按原文结构、顺序、观点；只补事实核对、署名、延伸阅读，补充放进 `.note-add`「本页补充（非原文）」。
- README 出处列：`nazha，nazha.co（2025-01-24）`
- 页脚：「本页根据 nazha 在 nazha.co 发表的《……》（2025-01-24）制作。」

**改写（adapted）**：原文当骨架，可重排章节、砍冗余、补缺口、换例子、多篇合并。页面里要分清哪些是原文观点、哪些是本页改写/补充：沿用同一个 `.note-add` 样式，标签写「本页改写（非原文）」或「本页补充（非原文）」；被重排/合并的章节在 `.lead` 或 `.src` 里注明取自哪篇。
- README 出处列：列出全部原文，如 `知乎答主 A（主）、B；公众号「某某」（2025-03）`，后可加 `；本页重新组织`
- 页脚：「本页以下列文章为骨架重新组织：……；章节顺序与例子为本页改写，已逐处标注。」

**原创（original）**：只有命题。先 WebSearch 多源交叉，先写提纲再写页面；事实尽量有两个以上独立来源，来源冲突时在页面里说明。全部内容都不是某篇原文，因此不使用「非原文」字样，改为在 `.meta` 写「本页为本仓库整理，非某篇文章的转述」，仍用 `.note-add` 标记争议点或未能核实之处。
- README 出处列：`本仓库整理，参考：A、B、C`（英文：`Compiled in this repo; references: A, B, C`）
- 页脚：不写「来源与署名」一段，直接列完整参考文献，每条都要是真实读过的来源。

档位判定与回报要求见 SKILL.md；用了哪一档、为什么，都要写进最终报告。
