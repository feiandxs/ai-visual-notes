    OIBench 与 CoreCodeBench：大模型编程到底有多强

    宣传里的模型能过谷歌面试、能当中级工程师；换成没见过的奥赛题和真实仓库里的核心代码，分数会掉到什么程度？这页把美团两套基准的榜单做成可排序、可切换维度的图，数据你自己翻。

    OIBench 用 212 道私有的信息学奥赛级题目测算法推理，最高分的 o4-mini-high 也只有 36.35%；CoreCodeBench 从真实 Python 仓库自动出题测工程能力，模型在代码修复和多函数协作上普遍掉队，而且写多个函数时不会先想清楚顺序。[1]
    MMeituan-M17 团队（美团技术团队） 交联合上海交通大学等机构

    原文：《美团开源 OIBench 与 CoreCodeBench：揭示大模型编程能力的真实水平》，Meituan-M17，美团技术团队博客（2025-07-17）。本页忠实于原文的叙述顺序。原文的表格和图都是图片，本页用两篇 arXiv 论文里的原始数据重画成可交互图表，另加了几处标注为「本页补充」的核对与延伸。

    01

    背景：评测集为什么不够用了

    同一个 GPT-4o，在 HumanEval 上通过 87.2%，到 OIBench 只剩 2.6%。差距从哪里来？

    原文表 2、表 3 的重画。切换维度看 OIBench 和其他六个代码评测集的差别：GPT-4o 通过率说明难度，题目数、每题测试数据量、标准解答行数说明规模。题目数和测试数据量跨度太大，用对数轴。点任意一行看说明。[2]
    原文归纳的四个局限
    饱和、区分度不足

    HumanEval、MBPP 的通过率普遍超过 90%，分不出顶尖模型的高下。

    数据泄漏

    Codeforces、USACO、LeetCode 的题公开在网上，可能已被预训练「见过」，分数虚高。

    人机对比难复现

    用 Codeforces Elo 对比模型与真人，周期长、选手水平波动大。

    效率指标粗糙

    运行时间、内存只给一个平均数，看不出不同题型上的差异。

    本页补充（非原文）：原文开头的几组对比（GPT-4o 在奥赛题上「个位数」、Claude 3.5 Sonnet 动态规划错误率 80% 以上、国内模型 MBPP 九成而 Codeforces Div.2 C 不足 15%、人类选手平均 70%）没有给出处，本页未能找到原始来源，只照录，不作核实。上图的 GPT-4o 数字来自 OIBench 论文附录表 4：HumanEval 取自 EvalPlus 榜单，CodeElo 是 pass@8，其余取各自论文；OIBench 的「题目数 250」是论文表 1 的写法，原文正文说 250 道候选、经难度验证保留 212 道。[2]
    02

    OIBench：一道题凭什么被收录

    题目要难、要私有、要有足够狠的测试数据。「难」怎么判断才不靠出题人的感觉？

    自动化难度闸门：题目由 ACM-ICPC 和信息学奥赛的高校教练团队编写。每道候选题先交给四个标杆模型去做，最多只有一个能解出才收录。点下面的模型，标记它在这道候选题上「解出 / 没解出」。
    抗污染实验：如果部分题目真的泄漏进训练数据，分数会虚高多少？论文从 OIBench 拿 100 道 C++ 题和官方解答，混进 10,000 条常规 SFT 数据，训练「泄漏版」与「基线版」两个模型对比，用 Risk Score 衡量提升了多少。拖动滑块感受这个公式。[2]
    原创、私有

    发布前逐题检索，确保没有在任何公开平台出现过。

    测试用例与标准解答

    每题配大数据量、边界情况的测试数据，以及通过全部测试的 C++ 标准解答。

    难度标注

    参照信息学竞赛与 Codeforces 难度评级，再叠加上面的模型闸门。

    中英双语

    每道题都有中文和英文版本。

    本页补充（非原文）：Risk Score 的公式与 0.00～0.01 的实测值来自 OIBench 论文 3.1 节与表 2，原文只说「风险分数几乎为零」。论文附录写明出题与翻译人员都按小时或按日计酬，人机对比的参赛者是来自国内高校、至少获过 CCPC 银牌的学生。原文说「数据均引用自 OIBench v1.0 论文（arxiv:2506.10481v3）」，但本页 2026-10 查询 arXiv 时该编号只有 v1；本页的数字取自 v1 的 HTML 版，与原文图片里的榜单一致。[2]

    主榜单：18 个模型、4 种语言

    最强的模型能拿多少分？推理模型、闭源模型、不同编程语言之间差多少？

    原文表 1、表 4 的重画（论文表 3）。指标是 AC 率：一道题的全部测试用例都通过才算对。切换语言维度、换成「伪代码提示」版本，或者按类型分组；下方的分组平均值由本页现场计算。[2]
    伪代码提示：把标准解答用 DeepSeek-R1 转成与语言无关的伪代码，连同题面一起给模型。这时考的不再是「想出解法」，而是「读懂解法并写对代码」。每条线左端是原题，右端是给了伪代码之后。点一行看提升幅度。
    本页补充（非原文）：原文第 3 条结论「基础模型决定上限」在伪代码版本里看得更清楚：DeepSeek-V3-base 给了伪代码后达到 27.45%，与它的指令版 DeepSeek-V3-1226（32.67%）同一量级，而 Qwen2.5-72B-base 与 Qwen2.5-72B 分别是 18.50% 和 19.00%。论文附录表 6 给出各模型的置信区间约为 ±0.5～3 个百分点，相邻模型的名次差距常在误差内，论文本身也说不打算为接近的模型排座次。[2]

    推理效率：多想几千个 token 值不值

    长思维链能提分，但每个模型「想」得一样划算吗？

    原文图 1 的重画：横轴是每题平均输出 token 数（以 2 为底的对数轴），纵轴是测试用例通过率（不是 AC 率）。圆的位置是本页从论文矢量图上读出的近似值，只用来看相对位置。点任意一个圆。[2]

    和 ACM 校队选手比一比

    o4-mini-high 大约能超过多少人类选手？为什么有的模型「时好时坏」？

    原文图 2 是小提琴图：每道题里模型在人类选手中的排名是一个点，点的分布画成「琴身」。这里先用条形图列出论文标注的平均超过人类的比例，点一个模型，右侧画出它所属的分布类型。排名规则参照 IOI：先比通过的测试用例数，相同再比运行时间；人类以最后一次提交为准。[2]
    OIBench 小结
    即使在模型突飞猛进的今天，真正高质量、高难度的算法题依然能难倒最先进的 AI。原文的判断是：未来的代码开发会是人机协同、优势互补，而不是谁单打独斗。
    本页补充（非原文）：人机对比只用了 OIBench 中的 44 道题，人类的匿名提交记录随数据集开源。论文把三种形态分别叫 Bass-shaped（低谷型）、Peanut-shaped（双峰型，形如花生）、Olive-shaped（橄榄型）；双峰型里只有 DeepSeek-V3-0324 不是长思维链模型。论文 5.2 节的错误分析指出，推理模型失败的主因是思维链太长，在 32,768 token 上限内没推完，并且出现明显的循环重复。右侧的琴身形状是按这三类画的示意，不是逐题实测密度。[2]

    单函数 vs 多函数：一到协作就掉队

    同一个模型，从写一个函数到同时写几个相互调用的函数，分数掉多少？修 Bug 是不是真的比写新代码难？

    原文表 5 的重画（论文表 3、表 4），16 个模型。每行两根条：上面是单函数，下面是多函数。切换场景和指标：AC@1 是第一次生成就通过全部单测的比例，AC Rate 衡量相对「什么都不改」时多通过了多少测试用例，更细。带 * 的模型开启了思考模式。[3]
    本页补充（非原文）：多函数 BugFix 只有 10 道题，AC@1 除 o1-mini（20%，即 2 题）外全是 0，论文也说这一列「差异不明显」，读的时候别太当真。AC Rate 的公式是（模型通过的用例数 − 原样就能通过的用例数）/（总用例数 − 原样就能通过的用例数）。[3]

    11

    总结与展望

    两套基准一起看，大模型写代码的边界在哪里？

    算法推理

    最强的推理模型在 OIBench 上 AC 率 36.35%，平均超过约 43% 的 ACM 校队选手，离顶尖选手还远。

    工程协作

    代码修复与多函数协作是普遍短板，单函数开发的 AC Rate 普遍在 70%～87%，多函数开发大多掉到 25% 以下。

    规划能力

    写多个函数时按提示顺序直接往下写，不根据依赖关系安排先后。

    方向

    原文期待模型从「代码片段生成器」进化为能分析、规划、解决复杂工程问题的开发伙伴，与人互补。

    换一套没见过、贴近真实的考题，大模型的编程能力就从「接近满分」回到了「还差得远」。这不是终点，而是指明了下一步该补什么。
