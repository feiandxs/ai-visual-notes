Cline 是怎么工作的
    可视化导读 · 基于 nazha 的博文

    AI Coding 编辑器
    没有那么神秘

    以开源的 Cline 为例，拆开一个 AI 编程插件：它怎么把任务交给大模型、怎么让模型"动手"、怎么一轮一轮跑到任务结束。8 个画面讲完。

    核心结论：Cline 的核心是系统提示词 + 大模型的指令遵循能力。一次任务会反复调用大模型很多次，直到做完。
    原文：《AI Coding 编辑器没有那么神秘 - How Cline works》，nazha.co，2025-01-24。本页为教学改编；原文未给出的细节在图中标注"示意"。
    01

    全景：一个任务 = 绕着圈跑很多次

    收集信息 → 问模型 → 解析模型给的"操作指令" → 执行 → 把结果塞回去再问。如此往复，直到任务结束。

    点击播放看一个任务跑完的全过程。小球走到哪，右侧就解释那一步在做什么。
    • 起点收集四样东西：系统提示词、用户自定义提示、用户输入、项目环境信息（有哪些文件、开了哪些 Tab）。
    • 模型不是直接改文件，它只是按指令输出文字；真正动手的是 Cline 解析这些文字后调用的工具。
    • 单次任务里，Cline 会多次调用大模型。
    02

    系统提示词：一份用 Markdown + XML 写的"说明书"

    它告诉模型：有哪些工具、怎么用 XML 格式"喊"工具、有哪些 MCP 服务器、用户立了什么规矩。

    左边是提示词的分层结构，点一层看原文片段。虚线框的两层是动态注入进来的。
    既然全靠模型"听话"，就不要它发挥：temperature 设成 0。
    • Cline 的系统提示词是类 v0 风格，Markdown 与 XML 混写，详细定义了 Tool Use 的规则和示例。
    • 已连接的 MCP 服务器也会被注入系统提示词；用户指令通过 .clinerules 注入。
    • 原文推测：Cursor、Windsurf 注入 .cursorrules 也是类似做法。
    03

    模型怎么"动手"？靠一套 XML 文本协议

    模型输出一段带标签的文字，Cline 用程序解析出工具名和参数，再真的去执行。

    三个来自原文的例子。看文字如何一步步变成一次真实操作。
    • 格式约定：工具名做外层标签，每个参数各一对内层标签。模型被要求"始终遵守"，否则解析不了。
    • 这不是什么特殊的 API 能力，只是提示词里的约定 + 一个解析器。
    • MCP 工具的调用也是同一套格式，只是多了 server_name 和 JSON 参数。
    04

    第一轮输入：把能塞的都塞进去

    用户的任务、@ 进来的文件和网页、再加一份项目环境快照，打包成一条消息发给模型。

    左：各种输入分别变成什么；右：最终发给模型的那封"信"（内容按原文示例）。
    • @ 没有什么科技含量：目录就列出结构，文件就读出内容，URL 就用 puppeteer 抓下来。
    • 环境快照包含：可见文件、打开的 Tab、当前时间、工作目录的文件列表、当前模式。
    • 原文推测：Cursor 这类编辑器可能对代码库做了嵌入索引，而 Cline 比较粗暴直接。
    05

    第一轮返回：先想一想，再给一个动作

    模型的回复通常两部分：<thinking> 里的分析，和一个用 XML 写的操作。Cline 解析后执行，并收集结果。

    左：模型逐字输出的回复（原文示例，任务是"实现一个太阳系的 3D 环绕效果"）；右：Cline 解析后做的事。
    模型能让 Cline 做的操作，原文列了四类：
    ⌘
    执行指令execute_command
    ✎
    读写文件read_file / write_to_file
    ⌕
    搜索内容在项目里找
    ⇄
    MCP 操作use_mcp_tool
    • 因为 temperature 是 0，模型的回复稳定地遵守格式，Cline 才能可靠地解析。
    • 执行的同时，Cline 会收集各类操作的状态信息，留给下一轮用。
    06

    第二轮起：把上一轮的结果连同全部历史再发一遍

    系统提示词 + 用户输入 + 模型回复 + 执行结果 + 新的环境快照，一股脑再发给模型，请它给下一步。

    点"再跑一轮"看消息堆叠和 token 用量上涨；撑到上下文窗口上限时，Cline 的策略是暴力截断。右侧刻度为示意。
    • 每轮消息结构（原文给出）：system → user(task + environment_details) → assistant(thinking + 指令) → user(指令结果 + 新的 environment_details) → …
    • 所以一次任务的 token 用量非常高，而且很容易撞上模型的上下文窗口限制。
    • 原文推测其他 AI 编辑器也是类似处理；作者用 Windsurf 时就遇到过"后面的回答重复前面"的现象。
    07

    MCP：把本地运行的服务器当工具接进来

    MCP 服务器提供额外的工具和资源；它们的说明被注入系统提示词，模型用同一套 XML 格式去调用。

    两条链路：① 服务器的能力被写进系统提示词；② 模型发出 use_mcp_tool，Cline 转发给服务器并把结果带回下一轮。
    • 原文引用的系统提示词说明：MCP 让系统与本地运行的 MCP 服务器通信，以扩展模型的能力。
    • 对模型来说，MCP 工具和内置工具没有本质区别，都是"按格式喊一声"。
    08

    所以，它真的没那么神秘

    一份写得很细的提示词、一套文本协议、一个循环。剩下的，交给模型的指令遵循能力。

    全景回顾：把前面 7 个画面串成一张图。
    理解了这套机制，也就更会用 AI 编辑器：给它清楚的任务、把相关文件 @ 进来、知道它会一股脑塞上下文所以别把对话拖太长。
    原文的三点推测（作者标注为推测，不是实锤）：

    .cursorrules 同理

    Cursor、Windsurf 的规则文件，大概率也是注入系统提示词。

    有的编辑器会做嵌入

    Cursor 可能对代码库建索引；Cline 则是直接把文件列表塞进去。

    截断是通用做法

    其他编辑器可能也是暴力截断上下文，所以长对话会"忘事"。
