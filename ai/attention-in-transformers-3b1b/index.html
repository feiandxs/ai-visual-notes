    同一个词，不同上下文00:00–04:30

    刚查表得到的 mole 向量在三句话里一模一样，模型怎么知道该是哪个意思？

    Transformer 先把每个 token 查表变成一个高维嵌入向量（视频里假设 token 就是整词）。这一步不看上下文，所以“mole”无论出现在“美国真鼹鼠（mole）”“一摩尔（mole）二氧化碳”还是“对肿瘤（mole）进行活检”里，起点向量都相同。注意力模块的任务，是根据周围的词算出该往这个通用向量里加什么，让它指向其中一个具体方向。

    点一句话。下面是嵌入空间的二维极简示意（真实空间有 12288 维）：灰色箭头是查表得到的通用 mole，选择上下文后，会加上一个变化量，指向对应含义。
    再看 Tower（塔）。“Tower”最初是个泛指高大建筑的方向；前面有“埃菲尔”，要更指向巴黎、法国、钢铁；再前面有“微型”，就不该再和“大而高”相关。勾选前缀看它怎样移动。

    02

    Query 与 Key：谁在问，谁来答06:14–08:27

    一个词怎样“问”别的词，又怎样被找到？答案是两个矩阵加一次点积。

    视频的例子句子是“a fluffy blue creature roamed the verdant forest”（一个蓬松的蓝色生物在葱郁的森林中游荡）。先只关心一件事：形容词调整名词。名词“creature”像是在问：“我前面有形容词吗？”这个问题被编码成较小维度（GPT-3 为 128 维）的查询向量 Q = WQE。另一个矩阵 WK 把每个词变成键向量 K，可看作“潜在的回答者”。键与查询方向越接近，点积越大，就说明这个词越“匹配”这个问题。

    拖动橙色圆点（或用滑块、键盘方向键）改变所选词的 Query；右边是它和每个 Key 的点积得分，以及 softmax 之后的权重。试着把 Query 转向 fluffy 和 blue 以外的方向。
    改写说明：真实的 Q、K 是 128 维向量，由训练得到，其“含义”远比“找形容词”复杂（视频也强调这只是为方便想象的设定）。这里的 2D 箭头和各词的方向是手工设定的示意数据，不是真实模型的权重。
    03

    打分、softmax 与遮罩：注意力模式08:27–13:10

    点积得分从负无穷到正无穷，怎样变成“每列加起来为 1”的权重？为什么后面的词必须被遮住？

    把每个 Key 和每个 Query 两两做点积，得到一张分数网格（每一列是一个 Query，每一行是一个 Key）。接着按列做 softmax，让每列都变成概率分布，这张网格就叫注意力模式。论文里把整件事写成一个公式（其中 V 稍后讲）：

    Attention(Q, K, V) = softmax(KTQ√dk)V

    除以 √dk（键查询空间维度的平方根）只是为了数值稳定。训练时，模型同时预测每个前缀之后的下一个 token，所以后面的词不允许影响前面的词，否则答案会提前泄露。做法是在 softmax 之前把这些位置设为负无穷，softmax 后它们变成 0，各列仍和为 1。这就是遮罩（masking）。直接设成 0 是不行的，列和就不再是 1。

    切换视图与开关。“点积分数”→“遮罩后”→“softmax 后”依次对应流水线的三步；点任意格子或列标题看具体数值。这里的 Query 与上一章共享：回去拖动，这张图会跟着变。
    为什么上下文长度是瓶颈？注意力模式的大小等于上下文大小的平方。拖动滑块看格子数。
    本页补充（非原文）：GPT-3 的上下文窗口为 2048 个 token[3]；视频只说“大小是上下文的平方”。后来出现的更长上下文方案，视频只一句带过，未展开。
    交叉注意力（视频 18:25 附近）：K 和 Q 来自两种不同数据（如翻译里的两种语言），此时通常没有遮罩，因为不存在“后面的词影响前面的词”。本页的 GPT 例子只用自注意力。

    Value：被搬运的信息13:10–15:40

    知道了谁与谁相关之后，真正加到 creature 上的到底是什么？

    第三个矩阵 WV 乘以某个词的嵌入，得到值向量：它回答“如果这个词对调整别的词有用，应该往对方的嵌入里加什么？”值向量和嵌入向量处在同一个高维空间。对注意力模式的每一列：用该列的权重缩放各个值向量，加总，得到变化量 ΔE，再加回原来的嵌入。对所有列都这样做，就得到一组更细致、带上下文的嵌入。

    逐步演示：形容词更新名词。以 creature 这一列为例。下面平面里每支箭头是一个值向量（二维示意）。点“下一步”，观察缩放、相加、叠加三步。若在上一章关掉遮罩，后面的 verdant 会“泄露”进来。
    改写说明：二维坐标、各词的值向量方向（“毛茸茸”朝上、“蓝色”朝右）是为演示而设；真实的值向量有 12288 维，方向含义由训练决定。

    单头的参数账：Value 为什么拆成两半15:59–18:22

    一个注意力头到底有多少参数？值矩阵为什么不直接做成 12288×12288？

    GPT-3 的嵌入维度是 12288，键查询空间是 128 维。WQ 与 WK 各有 128 行、12288 列，每个约 150 万参数。值矩阵若做成输入输出都在大嵌入空间的方阵，是 12288×12288，约 1.5 亿，比前两个大约百倍。实际做法是把它写成两个小矩阵的乘积：值降维（12288→128）和值升维（128→12288）。这是视频的叫法，并非通用术语。于是四个矩阵大小一致，合计约 630 万参数。

    点矩阵看形状与参数量；切换“值矩阵”的两种做法，看参数量差多少。
    改写说明：中文字幕里此处的“约 1500 万参数”与英文字幕/算术不符。12288×12288 = 150,994,944，即约 1.5 亿，英文原话为 “about 150 million”，本页按 1.5 亿处理。

    多头注意力与输出矩阵19:20–23:15

    上下文影响含义的方式有很多种，一个头够吗？多个头的建议怎样合在一起？

    “他们撞毁了”出现在“车”之前，会对车的形状和结构形成预设；文章里同时出现“魔法师”和“哈利”，暗示哈利·波特，若还有“女王”“萨塞克斯”“威廉”，哈利就该更新为王子。每一种上下文更新方式，都有不同的 Q、K 参数（不同的注意力模式）和不同的 V 参数（要加入什么信息）。所以完整的注意力块并行运行很多个头（GPT-3：每块 96 个）。每个头对每个位置给出一个建议的变化量，所有头的建议加在一起，再加到原来的嵌入上，就是该位置的输出。

    参数量计算器：WQ、WK、WV、WO 加起来多少16:00–24:40

    GPT-3 的所有注意力头一共有多少参数？占全部 1750 亿的多少？

    默认值就是视频里的 GPT-3：嵌入维度 12288、键查询维度 128、每块 96 头、共 96 层。改动任何一个数，下面的账都会现场重算。

    调参数。默认值应当得到视频里的结果：每矩阵约 157 万 → 每头约 630 万 → 每块约 6 亿 → 全部约 580 亿（略少于 58 B）→ 约占总参数的三分之一。
    08

    层层叠加：注意力为什么成功23:19–26:09

    一次注意力之后就结束了吗？为什么占了所有关注，参数却只有三分之一？

    拖动层数。数据不止经过一个注意力块：它还会经过多层感知器（MLP），两种操作反复交替。越深的层，嵌入从其他嵌入里吸收的东西越多，也越抽象。

    深层嵌入希望能编码更高级、更抽象的概念：情感、语调、是否是一首诗、与作品相关的基本科学事实，而不只是描述和语法结构。GPT-3 共有 96 层，注意力的键、查询、值（以及输出）参数合计约 580 亿，只占 1750 亿的约三分之一；大部分参数其实在注意力之间的 MLP 模块里，下一章会专门讲。

    视频最后的观点：注意力成功的原因，并不是它激发了某种特定行为，而是它极其适合并行计算，可以用 GPU 在短时间内完成大量运算。过去十到二十年深度学习的一个重要经验是：规模放大会带来模型性能的巨大提升，所以适合并行的架构占据巨大优势。

    一句话：Q 与 K 决定“看谁”，softmax 加遮罩得到权重，V 决定“搬什么”；多个头并行，输出矩阵合并；再叠 96 层，与 MLP 交替。
