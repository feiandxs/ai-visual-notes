Cline 如何自动编程
    可视化导读 · 基于 Heycc 的实测拆解

    DeepSeek R1 + Cline
    是怎么“全自动”写代码的？

    作者在本地架了一个代理，把 Cline 发给模型的每一个 prompt 都打印出来。本页把这场实测拆成 10 个画面：一句指令进去，几轮对话之后，代码出来了。中间到底发生了什么？

    核心结论：Cline 是一个 ReAct 思维链循环 Agent。它靠一份超长的 system prompt 和 XML 格式的工具调用，让模型“思考 → 调一个工具 → 看结果 → 再思考”，直到任务完成。代价是 Token 消耗巨大。
    原文：Heycc，2025-02-11，ihey.cc · 实测工具：Roo Code（Cline 的 fork）+ DeepSeek R1（硅基流动 API）· 本页为教学改编，所有 prompt、工具调用和数字都取自原文。
    01

    Cline 是什么：住在 VS Code 里的编程 Agent

    它能改文件、跑终端命令、用浏览器，并且可以接任何兼容 OpenAI API 的模型，包括本地模型。

    点击右侧条目，看 Cline 在 VS Code 里“看得见、摸得着”的四个区域。
    • 开源，Apache 2.0，fork 很多。最火的是 Roo Code（原名 Roo Cline），作者实测用的就是它。
    • 在 OpenRouter 的工具排行榜上，Cline 排第一名。
    • DeepSeek R1 爆红后，Cline 官方专门兼容了 DeepSeek、Gemini 的 Thinking 输出。
    02

    怎么偷看它的 prompt：架一个代理

    在 Cline 和模型 API 之间插一个本地 proxy，把每次请求原样打印出来。

    请求从 VS Code 出发，经过本地代理，再到硅基流动的 DeepSeek R1 服务。代理只做一件事：打印。
    • Cline 的 system prompt 在源码里就能找到，约 800 行、5 万字符。但那是静态的，看不出运行时行为，所以才需要代理。
    • 代理源码和完整 prompt 作者放在了 GitHub（见页脚）。
    03

    一次请求长什么样

    用户只打了一句话，Cline 真正发出去的却是三样东西：超长 system prompt、任务、环境快照。

    左：发给 DeepSeek R1 的请求结构（点击节点看说明）。右：environment_details 里的六个字段，原文逐一注解。
    • 用户唯一手动输入的文字：write a python demo to chat with api.openai.com。
    • 温度设为 0，模型 deepseek-ai/DeepSeek-R1。
    04

    第 1 轮：R1 一口气想干完，被 Cline 打断

    R1 先 <thinking>，然后连续输出 4 个工具调用。Cline 只执行第一个，其余全部拦下。

    回放 R1 第 1 轮的输出流。绿色 = Cline 执行了；红色 = 被拦下。文字取自原文。
    • system prompt 规定：一轮只能用一个工具，而且要放在消息末尾。R1 没守规矩。
    • 第一个 write_to_file 生效后，Cline 在界面上提示用户 Save。点 Save，自动进入第 2 轮。
    05

    整个任务的多轮时间线

    除了第一句指令，后面每一轮的“用户消息”都是 Cline 自动拼的：工具结果 + 被拦下的提醒 + 新的环境快照。

    点击任一轮，看这一轮 Cline 发了什么、R1 回了什么。下方是环境快照里 Current Context Size 的真实数字。
    • 触发第 2 轮的不是人，是 VS Code 底部 PROBLEMS 面板里的 flake8 报错。Cline 能读到它并喂给模型。
    • 原文指出 Context Size 这个数字“应该统计不准”：第 2 轮显示 1191 万 token，占比 9307%。
    • R1 始终没能修好 flake8 的空行要求，后面几轮反复修改、反复失败，原文略去了这些轮次。
    06

    每一轮内部：ReAct 循环

    感知环境 → 思考 → 输出一个工具 → Cline 解析并执行 → 把结果回填 → 再来一轮。

    环会自动转动。如果允许自动执行所有操作，它会一直转到模型认为任务完成。
    07

    原文展示的轮次里，工具被调了多少次

    14 次调用，只有 6 次真正走到执行。一大半被“一轮一工具”的规则拦下。

    按原文逐轮数出来的统计（第 1～3 轮、失败案例、人工干预后、最后一轮）。
    Cline 的工具不是 JSON function call，而是 XML 标签。原文总结了为什么。
    08

    工具执行失败了怎么办

    apply_diff 要求搜索块和文件 100% 相似。只有 40% 时 Cline 拒绝修改，把错误详情喂回去，R1 反思后先 read_file。

    一次真实的 apply_diff 失败：R1 记的行号已经过时。
    最后是人出手：作者手动改了文件。Cline 检测到人工编辑，把 diff 和整个文件全文重新发给模型。
    09

    DeepSeek R1 在这里扮演什么角色

    它负责“想”和“说”，Cline 负责“做”和“管”。强如 R1，也没能严格遵守 system prompt。

    仅限原文提到的事实。
    10

    总结：画面很美好，代价也很高

    一个写 chat demo 的小任务，累计消耗约 100 万 token。

    原文的三条结论。
    对做 Agent 应用的人来说，Cline 的启发在于：靠 prompt 就能搭出一个能跑的 Agent。工具定义、示例、规则全写在 system prompt 里，用 XML 标签管理，不依赖模型的 function call 能力，解析出错也容易恢复。
